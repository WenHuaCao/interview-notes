# 每天 21:00 的标签整理任务

在 ChatGPT 网页版 Work 中连接 GitHub 插件，先手动运行下面提示词，确认可以读取题库、写入标签并回读，再创建定时任务。

- 名称：拾问 · 每日标签整理
- 频率：每天 21:00
- 时区：Asia/Shanghai（北京时间）
- 运行环境：ChatGPT 网页版云端；不使用本地路径或本机脚本。

## 创建任务时发送的提示词

```text
请创建一个每天北京时间 21:00（Asia/Shanghai）运行的云端定时任务，名称“拾问 · 每日标签整理”。每次按以下说明执行：

使用已连接的 GitHub 插件，读取 WenHuaCao/interview-notes 默认分支 main 的 WORKFLOW.md 和 content/tags.json，执行其中的“每日标签整理”。所有持久数据从 GitHub 获取，不访问我电脑的本地文件。

枚举 content/questions/ 下的真实记录，只处理没有 taggedAt 或 updatedAt 晚于 taggedAt 的记录，跳过 content/examples/。根据完整问答和追问统一标签、归并同义概念、保留 manualTags，并维护标签描述。新增标签先写入字典，再更新题目引用。保留原始问答正文、ID、首次提问时间、来源和 updatedAt；整理仅更新 tags、taggedAt 及标签字典。

每次更新前读取最新文件及 SHA；发生冲突重新读取、重新判断，最多重试两次，仍失败则报告，不覆盖新内容。写入后回读核对。只有实际整理了内容，或失败、需要我处理权限时才通知；没有待处理记录时保持安静，不重复提交。

请确认任务已启用，并报告保存后的时区、下次运行时间及状态。如果当前账户无法创建任务，直接说明，不要把这段提示词的存在当作任务已经创建。
```

## 验收

在 Scheduled 中核对任务为启用状态、时间为北京时间 21:00。手动试跑一次，确认使用网页版的 GitHub 连接；如果没有真实待整理记录，应不产生提交。新记录完成一次整理后，重复运行应无变更。需要用户授权、配额不足或工具不可用时应明确报告失败。

本仓库不保存 ChatGPT 账户凭证，也不以 GitHub Actions 替代该模型整理任务。GitHub Actions 只负责检查、构建与发布博客。
